# 一、下载升级：运行时配置热更（本人手写部分）

## 1.1 为什么放在主模块而不是插件

`ARPGAIAgent` 插件的设计铁律是「**不反向依赖游戏模块**」——它靠反射读 AttributeSet，
做成可独立交付。热更新要读写游戏自己的数值（`EnemyMaxHealth` 等），属于业务，
塞进插件就会破坏这条约束。所以新类放在 `Source/ARPGDemo/` 下。

模板直接照抄 `Plugins/ARPGAIAgent/Source/ARPGAIAgent/Public/ARPGAIAgentSubsystem.h`：
```cpp
#include "Subsystems/WorldSubsystem.h"
UCLASS()
class XXX_API UXXXSubsystem : public UWorldSubsystem
{
    GENERATED_BODY()
public:
    virtual void Initialize(FSubsystemCollectionBase& Collection) override;
    virtual void Deinitialize() override;
};
```

## 1.5 时序

```
Initialize()                                    [GameThread]
  └─ FetchVersionJson()
       └─ HTTP GET {BaseUrl}/version.json       [SetTimeout 5s]
            ├─ 成功 → 解析 { "version": 3, "url": "balance_v3.json" }
            │         ├─ version <= AppliedVersion → 结束（不重拉，含防降级）
            │         └─ version >  AppliedVersion → FetchBalanceJson()
            │                └─ HTTP GET → 解析 → SanitizeConfig → ApplyBalance()
            │                      └─ AsyncTask(GameThread) 里写 Applied + 广播
            └─ 失败 / 超时 / 解析失败 → FallbackToLocal(原因)
```

**两条必须遵守的线程规则**（照抄插件的四条铁律）：
- `FHttpModule::Get()` 的 `CreateRequest` / `ProcessRequest` **只能在 GameThread 调**；
- 想让 JSON 解析不占主线程就显式
  `Request->SetDelegateThreadPolicy(EHttpRequestDelegateThreadPolicy::CompleteOnHttpThread)`，
  然后自己 `AsyncTask(ENamedThreads::GameThread, ...)` 把结果搬回主线程。
  出处：`Engine/Source/Runtime/Online/HTTP/Public/Interfaces/IHttpRequest.h`（`SetTimeout` 在 317 行）。

## 1.6 降级清单（这段是面试的加分项，逐条实现并实测）

| 场景 | 处理 |
|---|---|
| URL 没配 | 直接用本地值，不打错误日志刷屏 |
| 连不上 / 404 / 500 | 记 `LastError`，用本地值 |
| 超时（>5s） | 同上，**游戏照常能玩**，这是热更的第一原则 |
| JSON 解析失败 | 同上 |
| **某个字段非法**（负数 / NaN / 超上限） | **逐字段回退**本地值，其它合法字段照常采用（不要整包丢弃） |
| **服务器版本比本地旧** | 忽略，防降级攻击 |
| 配置拉到时敌人已生成 | 靠 `OnBalanceApplied` 广播刷新，敌人侧用 `TWeakObjectPtr` 保护 |

**跨类通信套路**：和破防用的 `State.BlockBroken` 一模一样 —— 子系统不知道谁关心配置，
只负责发信号；敌人订阅委托自己刷新。别在子系统里反向持有敌人列表。

### ⚠️ 状态文字改走 UMG，不要用 C++ 的 NSLOCTEXT（11-02 六轮实测结论）

**实测结果（每轮都用 `UnrealEditor-Cmd.exe -run=GatherText` 跑真实命令验证）**：

| 轮次 | 实验 | 结果 |
|---|---|---|
| 1 | 原配置：`SearchDirectoryPaths=Source/`（相对）+ `IncludePathFilters=Content/*` | 收到 2 条 UMG，**另有 82 条材质参数名噪音**，源码 0 条 |
| 2 | 改绝对路径 `D:/Warrior/ARPGDemo/Source/` + 收窄到 `Content/Blueprint/Widget/*` | 2 条 UMG，噪音清零，源码仍 0 条 |

```cpp
    {
        GConfig->SetString(TEXT("ARPGDemo.Localization"), TEXT("Culture"), *Culture, GGameIni);
        GConfig->Flush(false, GGameIni);
    }
}
```

⚠️ **最大的坑**：切 culture 后，屏幕上**已经存在**的 TextBlock 不会自动刷新——
`FText` 只在控件重新求值（构造 / `SynchronizeProperties`）时才取当前语言。
最省事的办法是**销毁 HUD 再重建**：

```cpp
HUDWidget->RemoveFromParent();
HUDWidget = CreateWidget<UARPGHUDWidget>(PC, HUDWidgetClass);  // 重新 Create
HUDWidget->AddToViewport();
```
不要去挨个 `SetText`，漏一个就出现「一半中文一半英文」。

调试期可以先走控制台命令，省得做按钮：`culture en`（再敲 `culture zh-Hans` 切回）。

⚠️ **测试环境坑**：编辑器（含 PIE）用的是**编辑器自身的语言**，切换可能看不出效果。
**用 Standalone Game 测才准**。打包前还要在
`Edit → Project Settings → Packaging → Advanced` 里把目标语言勾上，
并把 **Internationalization Support** 设为 `All`，否则打包后只有一种语言。

# 三、音频并发管理（以资产配置为主）

## 3.1 现状

全项目只有 2 处播音效，都是
`UGameplayStatics::PlaySoundAtLocation(MeshComp, HitSound, HitLoc)`：
- `Source/ARPGDemo/Private/AbilitySystem/UARPGAnimNotify_MeleeHit.cpp:135`
- `Source/ARPGDemo/Private/AnimInstance/ARPGAnimNSMeleeHitWindow.cpp:413`

⚠️ 这个函数**没有 concurrency 参数**（`KismetGameplayStatics.h` 里的签名只有
Sound / Location / Rotation / Volume / Pitch / StartTime）。
所以并发控制**只能挂在 SoundBase 资产上**——这本身就是个能讲的点：
音频的并发策略属于资产管线层，不是调用层。

## 3.2 操作步骤

1. Content Browser → 右键 → **Sounds → Sound Concurrency**，命名 `SC_HitLimit`。
2. 打开它，设置：
   - **Max Count** = 4（同时最多 4 个，超出的按规则处理）
   - **Resolution Rule** = `Stop Oldest`（停掉最老的，保证最新的命中反馈一定能听到）
   - **Volume Scale** = 0.8（叠加时整体压一档，这是**防爆音**的关键）
3. 打开命中音效资产（`SC_BlockedMelee` 等）→ Details → 找 **Concurrency** → 数组里加 `SC_HitLimit`。
4. 相同的音效资产如果有多个（格挡、受击、死亡），各建一条或共用一条，按音色分组。

## 3.3 两个加分项（做完「音视频」这章更站得住）

**① Sound Class 分组 + 音量滑块**
- Content Browser → **Sounds → Sound Class**，建 `SC_BGM` / `SC_SFX` / `SC_UI`；
- 建一个 **Sound Mix**（`Sounds → Sound Mix`），里面挂这三个 Class；
- 三个音效资产的 Details → **Sound Class** 指到对应 Class；
- C++ 控制音量：
  ```cpp
  UGameplayStatics::SetSoundMixClassOverride(this, SoundMix, SoundClass_SFX, Volume01, 1.f, 0.2f);
  ```
  出处：`KismetGameplayStatics.h`（函数名以实际签名里的 `FadeInTime` 参数为准）。

**② 按物理材质切音效（动态音频）**
```cpp
EPhysicalSurface Surface = UPhysicalMaterial::DetermineSurfaceType(Hit.PhysMaterial.Get());
if (USoundBase** Found = SurfaceSounds.Find(Surface)) { PlaySound(*Found); }
```
`FHitResult::PhysMaterial` 是 `TWeakObjectPtr<UPhysicalMaterial>`，
要 `.Get()` 再判空。给石头 / 木头 / 肉体三种 SurfaceType 配三种音效，
用 `TMap<EPhysicalSurface, TObjectPtr<USoundBase>>` 查表。

## 3.4 演示

- 连击 10 次快速命中 → 音效不叠加爆音（并发上限 4 + 音量自动压 0.8）；
- （加分）打石墙 vs 打敌人 → 不同音效；
- （加分）设置里拖 SFX 滑块 → 音效变小，BGM 不受影响。
