0. 核心认知：这条视频到底在拍什么

先纠正一个容易跑偏的点：「拍基础功能」和「提供解决方案」是两件事。 面试官看这条视频，不是想看「你会不会播个音效」，而是想看 「你有没有遇到问题、能不能定位、能不能给出有理由的方案、还能不能验证」。

所以每一章都套同一个骨架，缺一章就补一章，别只放画面：

问题（不这么干会怎样） → 方案（为什么选它，不选别的） → 实证（日志 / stat / 前后对比）
反面教材：「第 3 章音视频」只放一段连击音效 → 面试官看完只知道你会 PlaySoundAtLocation。
正面教材：先说「同一帧 10 个敌人同时受击，10 个音效叠加会削波爆音」→ 给方案「并发上限 4 + Resolution Rule=Stop Oldest + Volume Scale 0.8，且并发策略挂在资产上而不是调用上」→ 屏幕上 10 连击实测不爆音。这一章才站得住。

七章总览（按拍摄顺序，不是实现顺序）

章方向要回答的问题（一句话）时长
1网络网络请求失败/超时，游戏还能不能正常玩？10s
2性能优化20 个敌人同屏时瓶颈在哪？我怎么定位、怎么压下去？12s
3音视频大量音效同时播放怎么防爆音？不同材质怎么自动切音效？12s

加片头 3s + 片尾 3s ≈ 90 秒。别贪长，90 秒看完的才是好视频。

1. 网络：关键是「降级」，不是「连通」

现状Build.cs 已加 HTTP/Json/JsonUtilities；Plugins/ARPGAIAgent/.../ARPGAIAgentRemoteClient.cpp:56-128 有现成的 HTTP 写法可照抄。
要补UARPGHotUpdateSubsystem（你手写，手册 1.4 有类骨架）。

拍摄脚本

镜头 A（正常）：控制台打出 [HotUpdate] version.json ok, remote=3, local=0 → [HotUpdate] balance applied, EnemyMaxHealth=300
镜头 B（断网）：Ctrl+C 掉 http.server，重启游戏 → [HotUpdate] fetch failed(超时/连接失败), fallback to local, EnemyMaxHealth=100
镜头 C（关键）：断网状态下正常打怪，游戏完全可玩 ← 这一帧才是重点

解说要点（面试话术）

  • 「热更的第一原则不是成功，是失败也不能影响可玩性。所以任何一环出错都走 FallbackToLocal()。」
  • 「逐字段降级而不是整包丢弃：一个字段非法（负数/NaN）只回退那一个，其它合法字段照常生效，避免运营改 10 个值错 1 个就全盘作废。」
  • 「防降级：服务器版本号比本地小就忽略，防止中间人回滚到旧配置刷分。」
  • 「FHttpModule::Get() 和 ProcessRequest() 只能在 GameThread 调；JSON 解析想挪走就用 SetDelegateThreadPolicy(CompleteOnHttpThread) 再 AsyncTask(GameThread) 搬回来。」
⚠️ 演示必须走本机：python -m http.server 8000 --directory D:\Warrior\ARPGDemo\Docs\hotupdate_demo。 你的代理 127.0.0.1:7890 没通，走外网录制必失败。

2. 性能优化：空白最大，也最能拉开差距

现状几乎空白，唯一可讲的是 BTService_ARPGPreception 的 1Hz 决策节流。
要补三件事：① 对象池 ② Significance Manager 分级 ③ 量化前后对比。

2.1 先做「可测量」，再做「优化」

顺序不能反。没有数字的「我优化了一下性能」在面试官那里等于没说。

stat unit          // 看 Game / Draw / GPU 三线程，谁最大谁就是瓶颈
stat game          // GameThread 里各 Tick 耗时
stat anim          // 动画更新开销
stat scenerendering // DrawThread
Unreal Insights    // 抓一段 trace，定位具体函数

2.2 三个具体抓手

手段做法面试说法
对象池 命中特效 / 投射物不再 Spawn-Destroy，改用池子复用。SpawnSystemAtLocation 的 ENCPoolMethod 先从 None 改成 AutoRelease。 「避免运行时 GC 抖动，把分配成本挪到加载期」
Significance 按「距玩家距离 + 是否在视野内」分三档：近处全量更新 / 中距降频 / 远处只跑移动。 「LOD 不止是模型，AI 和动画也要 LOD」
AI 降频 已有 1Hz 决策，再补：黑板更新、EQS 查询都挂到同一个节流时钟上。 「感知和决策不需要逐帧，人眼分辨不出来」

拍摄脚本

左半屏放 stat unit，右半屏放 20 敌人场景。
先录「优化前 20 敌人」→ 切「优化后 20 敌人」→ 两屏并排放，数字用红框圈出来。

3. 音视频：并发防爆音 + 材质切音效

现状全项目只有 2 处播音效，都是 UGameplayStatics::PlaySoundAtLocation（UARPGAnimNotify_MeleeHit.cpp:135、ARPGAnimNSMeleeHitWindow.cpp:413）。
这本身就是个能讲的点：PlaySoundAtLocation 的签名里没有 concurrency 参数， 所以并发策略只能挂在 SoundBase 资产上 —— 说明「音频并发属于资产管线层，不是调用层」。 能讲出这句话，说明你是真的看过引擎签名，不是抄的教程。

3.1 操作步骤

  1. Content Browser → 右键 → Sounds → Sound Concurrency，命名 SC_HitLimit。
  2. 打开设置：
    • Max Count = 4（同时最多 4 个）
    • Resolution Rule = Stop Oldest（停最老的，保证最新命中反馈听得到）
    • Volume Scale = 0.8（叠加时压一档，这是防爆音的关键）
  3. 打开命中音效资产 → Details → Concurrency → 数组加 SC_HitLimit。

3.2 加分项（做了「音视频」这章才完整）

① Sound Class 分组 + 音量滑块

建 SC_BGM / SC_SFX / SC_UI（Sounds → Sound Class）
建 Sound Mix（Sounds → Sound Mix），挂这三个 Class
音效资产 Details → Sound Class 指向对应 Class
C++：
UGameplayStatics::SetSoundMixClassOverride(this, SoundMix, SoundClass_SFX, Volume01, 1.f, 0.2f);

② 按物理材质切音效（动态音频）

EPhysicalSurface Surface = UPhysicalMaterial::DetermineSurfaceType(Hit.PhysMaterial.Get());
if (USoundBase** Found = SurfaceSounds.Find(Surface)) { PlaySound(*Found); }

⚠️ FHitResult::PhysMaterial 是 TWeakObjectPtr<UPhysicalMaterial>，要 .Get() 再判空。给石头/木头/肉体三种 SurfaceType 配三种音效，用 TMap<EPhysicalSurface, TObjectPtr<USoundBase>> 查表。

拍摄脚本

主镜头：连击 10 次快速命中 → 音效不叠加爆音（并发 4 + 音量自动压 0.8）
加分 1：打石墙 vs 打敌人 → 不同音效
加分 2：设置里拖 SFX 滑块 → 音效变小，BGM 不受影响

「输入缓冲」是很能讲的小优化：攻击动画播到后 20% 时按攻击键，不算丢输入， 存进缓冲里等当前动作结束立刻放。玩家体感是「连招不吞键」。 实现就一个 TArray<FGameplayTag> BufferedInput + 一个 0.2s 的定时器。

5. 安全：把「配置被改坏」当正常流程处理

现状完全空白。但这章最省事——热更子系统的 SanitizeConfig() 一写，第 1/5/7 三章素材一起出。

5.1 威胁模型（面试要先说清你在防什么）

威胁兜底
配置文件被改坏 / 传输截断逐字段范围校验，非法回退本地
中间人降级到旧版本版本号单调不减，小了就忽略
数值被改成 Infinity / NaNFMath::IsFinite() + 上界钳制
玩家改本地内存（进阶）关键判定放服务端；单机场景明确说「不防这个」
⚠️ 面试诚实线：纯单机 ARPG 防不住内存修改器，别吹。 正确的说法是：「单机下我保证的是配置完整性和降级容错， 真正的数值防作弊需要把判定放服务端，这是架构层面的选择，不是这个 Demo 的目标。」 说清边界比硬吹更能加分。

拍摄脚本

把 balance.json 里 EnemyMaxHealth 改成 -1 → 重启 → 日志打出 invalid EnemyMaxHealth(-1), use local(100)， 同时 EnemyAttackPower 仍然生效（证明是逐字段回退不是整包丢弃）。

时序

Initialize()                                    [GameThread]
  └─ FetchVersionJson()
       └─ HTTP GET {BaseUrl}/version.json       [SetTimeout 5s]
            ├─ 成功 → 解析 { "version": 3, "url": "balance.json" }
            │         ├─ version <= AppliedVersion → 结束（防降级 + 不重复拉取）
            │         └─ version >  AppliedVersion → FetchBalanceJson()
            │                └─ 解析 → SanitizeConfig → ApplyBalance()
            │                      └─ AsyncTask(GameThread) 里写 Applied + 广播
            └─ 失败 / 超时 / 解析失败 → FallbackToLocal(原因)

降级清单（逐条实现并实测）

场景处理

9. 风险与坑位提醒

  • 改 .h 必须关编辑器完整 Build，Live Coding 对头文件改动不可靠（今天已经栽过一次：状态文字不显示就是因为 Live Coding 产物早于改动）。
